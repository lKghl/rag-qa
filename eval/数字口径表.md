## 1. 行为符合率 28/28

- **来源**：`eval.py` 的 `check_behavior()`，2026-10-22 全量跑，结果落盘 `eval/eval_results.md`。
- **分母**：30 条 − 2 条边界用例（E14「什么是深度学习？明天天气怎么样？」、E30「什么是线性回归？明天天气怎么样？」）。这两条是复合输入，违反"一题一问"契约，按设计单列不计分。
- **判定规则**：`answer` 类型要求答案含「引用资料：」且检索候选非空；`refuse` 要求含拒答句；`greet` 要求含助手名且候选为空。
- **表述边界**：这是"是否按契约行事"，**不是"答案正确率"**。答案质量由忠实度指标单独负责。

## 2. 检索命中率 17/18

- **分母**：20 条有预期章节的用例 − 2 条边界用例 = 18。
- **判定**：前 k 个候选的 heading 里出现预期章节号的**子串**即为命中。
- **关键实现细节**：判定走 `search_info()` 的原始检索结果，不走 `ask()` 返回的 `retrieved`。原因是拒答时 `ask()` 会清空出处——若用界面出处判定，测的就变成显示逻辑而非检索能力。这个坑踩过，`eval.py:79` 是修好后的版本。
- **已知局限**：子串匹配存在前缀碰撞风险（「3.1」理论上可撞「3.10」）。本轮 30 条未出现误命中，但这是口径缺口，不是零风险。
- **表述边界**：不能说"检索准确率 94%"。它衡量的是"正确章节进前 5 的比例"，不衡量排序质量，也不等于答案正确。

## 3. 忠实度 93/93

- **分母**：20 个作答用例拆成 93 个可核查论断，逐条到其引用块里找依据。证据逐条列在 `eval/faithfulness.md`。
- **注意边界用例**：20 条作答用例**包含** E14/E30 两条边界用例（其论断共 9 条）。它们在行为符合率上不计分，在忠实度上计入——既已作答，论断就必须有据。两个指标的边界处理有意不同。
- **为什么不用 LLM 裁判**：裁判本身会幻觉，且无法自证；30 条规模人读得完。
- **表述边界**：
  - **不许裸说「忠实度 100%」**——必带分母「93 个论断 / 20 个作答用例，人工逐条核查」。
  - 「零幻觉」只能限定在"这 20 条样本、单一语料"内，不能外推。

按块内中文占比分桶（`measure_tokens.py`）：

|:---|---:|---:|
| 15–30% | 293 | 0.630 |

| 纯中文基准 | — | **1.000** |

- **结论**：0.65 是"混合文本、字符口径"的平均值，被英文术语/代码/数字拉低。**纯中文是 1 字 ≈ 1 token。**

### 为什么字符与 token 没有固定换算关系

`bge-small-zh` 用的是 BERT 的 **WordPiece** 词表（21128 词），规则与 GPT 系 BPE 不同：

**中文：按单字切，1 字 = 1 token**（深度学习的 → 深/度/学/习/的，5 token / 5 字符）

**英文：按子词切**，词表收录的高频词整词一个 token，词表外的词被拆成「词根 + `##` 尾缀」：

| 输入 | token / 字符 | 切分 |
|:---|:---:|:---|
| deep | 1 / 4 | deep |
| learning | 1 / 8 | learning |
| softmax | 2 / 7 | soft / `##max` |
| embedding | 4 / 9 | em / `##be` / `##dd` / `##ing` |
| transformer | 5 / 11 | t / `##ran` / `##s` / `##form` / `##er` |
| backpropagation | 5 / 15 | back / `##pro` / `##pa` / `##ga` / `##tion` |
| PyTorch | 1 / 7（`[UNK]`）| 词表未收录，整词丢失 |

**数字**：1–4 位整数多为 1 token；长数字、小数点、科学计数法会拆开（`12345678` → 2 token，`3.14159` → 4 token，`1e-5` → 4 token / 4 字符）。

**0.63 这个系数怎么来的**（以中文 15–30% 档为例）：`0.2 × 1.0（中文） + 0.8 × 0.54（非中文） = 0.63`。非中文部分只有 0.54，原因有二：

1. 英文单词字符多、token 少（9 字符的 embedding 只要 4 token）；
2. **空格不产生 token**——`"deep learning"` 13 字符只切出 2 个 token，中间空格算 0 token。

所以 1 个字符可能对应 0 个 token（空格）、1 个 token（中文/符号）、或 1/3 个 token（常见英文词）。**不存在能反推的固定系数**，这是"字数 × 0.65"失效的机制原因。

**两个反直觉点**：

- **代码符号是 1 字符 = 1 token，不省 token**：`[[1,2],[3,4]]` 为 13 token / 13 字符，`\frac{a}{b}` 为 10 token / 11 字符。只有英文标识符部分才省，符号逐字计数。
- **`[UNK]` 会整词丢失**：`PyTorch`、`Linear` 均不在词表内。这是检索质量的隐性风险——纯英文术语提问会被碎裂化。该判断为推断（词表来自中文语料、大小写敏感），未做纯英文提问的对照实验。

**对项目的实际含义**：512 这个上限只约束 bge（向量模型），而 DeepSeek 用另一套 tokenizer（BPE 系），同一段文本算出的 token 数不同。不能用 0.65 推算 prompt 预算。
- **表述边界**：
  - 不许说「1 个中文字符 ≈ 0.65 token」——这是张冠李戴，中文是 1.00。
  - 不许用「字数 × 0.65」估算本项目的 token 占用——中文密集块会低估近 40%。

## 8. top_k 消融（`eval/topk_sweep.py`）

20 条有预期章节的用例，检索上限放到 15，记录正确块的首次命中排名：

| k | 契约内 18 条 | 全量 20 条 |
|:---:|:---:|:---:|
| 1 | 9/18 | 10/20 |
| 3 | 17/18 | 18/20 |
| **5（现行）** | **17/18** | **19/20** |
| 8 | 17/18 | 19/20 |
| 15 | 18/18 | 20/20 |

排名分布：第 1 名 10 条、第 2 名 4 条、第 3 名 4 条、第 4 名 1 条、第 11 名 1 条。

- **可下结论**：
  - k=3 与 k=5 在契约内口径下**持平**。k=5 的唯一增益是边界用例 E14（排名 4），而边界用例按设计不计分。
  - k 从 5 加到 8/10 零增益，纯浪费上下文与 token。
  - k=15 才能捞回 E06（排名 11），代价是 5→15 的三倍噪声。
- **不能下结论**：
  - 不能说"k=5 是消融选出的最优"。数据只能说"5 保住了 3 的水平并给复合输入留了 buffer"。
  - 本消融只测检索层，没测生成层。k 变大会稀释上下文、增加干扰，是否伤害答案质量需要 LLM 调用验证，**未做**。
- **附带发现（反证距离阈值）**：E06 的 top1 余弦距离 0.1808，在全部用例里算近的，但内容是错的。距离小 ≠ 相关，所以没有加距离阈值。

## 10. 口径一致性审计（2026-10-25）

对全项目文档与数据做交叉核对，结论如下。

**已核对通过（无问题）**

| 项 | 核对方式 | 结果 |
|:---|:---|:---|
| 评测集构成 15/6/4/4/1 | 读 `qa_set.json` 统计 | 与 README 一致，合计 30 |
| 预期章节真实性 | 20 条前缀对 596 个书中标题 grep | **全部找到**，"经 grep 实证"为真 |
| 预期章节是否入库 | 对 869 块 heading grep | **全部在库**，E06 的 miss 属排序问题 |
| 清洗表 9 项数字 | 用 `ingest.py` 正则对原文复算 | **9 项全对**（448/138/84/155/4088/1/1550/29/31）|
| 块账 | 逐级复算 | 1552→1409→1352→869，1409−57−483=869 |
| 命中率与 top_k 一致 | `topk_sweep.py` k=5 | 契约内 17/18，与 README 一致 |
| 前缀碰撞是否造成误判 | 逐条查首次命中块的 heading | **零误命中**：20 条全部落在正确章节的子节（如 E17 命中 `3.1.2 线性回归的表示方法`，非 `3.11.x`）|
| 忠实度 20 条 / 93 论断 | 读 `faithfulness.md` 明细 | 20 条明细可逐条对应，论断数自洽 |

**发现的 3 处不一致**

1. **边界用例（E14/E30）在两个指标里处理不同**：行为符合率排除它们（28/28 的分母），忠实度却把它们计入（20 个作答用例含这 2 条，93 个论断含其 9 条）。原文未说明成因，读起来像矛盾。
   → **处理**：不改数字，补说明——行为指标考察"是否遵守单问题契约"，违规输入按设计不评分；忠实度考察"只要产出了论断，就必须有据"，边界用例既已作答就必须核查。两者口径不同是**有意的**，不是错误。
2. **`results_baseline.md` 缺少基线标识**：标题与 `eval_results.md` 完全相同，无日期、无"脏库"、无"15 条旧集"字样，README 链接过去会被误读为又一份现行结果。
   → **处理**：在该文件头部加基线声明。
3. **"本轮未出现误命中"缺证据**：原文只是断言。
   → **处理**：补上逐条查验结果，并量化碰撞空间（库内含 `3.1` 的 heading 有 99 块，其中 85 块属 3.10/3.11 等越界章节）。

**新增发现：80 字重叠的实际代价**

869 块中有 **298 块（34.3%）** 与其他块存在 ≥80 字的完全重复窗口；若每块都含 80 字重叠，重复量上界约 68,865 字（占总字符 24.8%）。重叠保住了跨块语义，但代价是 top5 里可能出现两个内容重叠的块、占掉名额。注：重复窗口中含有原文自身重复的内容，与 overlap 机制产生的重复未做区分。

## 表述纪律（四条）

1. **每个比率带分母。** 「17/18」不是「94%」。分母不同时不许互相比较。
2. **归因分开写。** 清洗解释命中率，提示词解释行为。混在一起说会被追问穿。
3. **事后合理化要标注。** 400 这个值是按最坏情况卡上限推出的，不是消融选出来的——承认它是"设计约束推导"，不是"实验最优"。
4. **未验证的说未验证。** 80 字重叠是惯例值；k 只测到检索层。这些不是短板，是诚实边界。
